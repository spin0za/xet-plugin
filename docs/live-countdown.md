# 直播详情页与直播间倒计时

适用范围：已授权网站的 `/detail/l_…/4` 直播详情页，以及 `/p/t_pc/live_pc/pc/l_…` 直播间，不限某个商家或直播 ID。只处理核实过的原生 Vue 组件，不处理任意同名文案。

## 真实页面核实

- 原生 `status-wrapper.__vue__` 提供 `time`（剩余毫秒数）、`status`、`liveStatus`、`count`、`getTime` 和 `formate`。
- 原生 `time` watcher 先调用 `getTime(count)`，再每秒调用一次；`getTime` 只执行 `count -= 1000`。后台标签页定时器被降频时，会少减很多秒。
- 时间由 `/api/xe.goods.detail.get/2.0.0` 返回的 `zb_start_rest_time` 提供。页面的 `zb_start_at` 已经过本地化处理，不能把显示字符串当成带时区的绝对时间重新解析。

## 修复

在经过后台站点授权、顶层 frame、文档和路由校验后，于 MAIN 世界安装小范围 Vue 适配器。旧接口响应以固定的 `performance.timeOrigin + responseEnd` 换算为墙上时间，再加服务器剩余时长得到截止时间；每次显示计算 `max(0, deadline - Date.now())`，不按回调次数递减。首次安装晚于响应时也会扣除已经过去的时间。不能使用当前墙上时间减 `performance.now()` 的差值重建旧响应时间，因为有些平台休眠期间性能时钟会暂停；新服务器 props 到达时直接使用交付时刻，而非已暂停的性能时钟基准。

如果页面清除了资源计时记录，则从原生当前剩余值接管；无法凭空恢复安装前丢失的时间，但接管后不会继续累积降频误差。更新服务器 props 时重新建立基准，同一轮 Vue 更新不会重复重置。

详情页保留原生 `getTime` 格式化、DOM、CSS 和到点 `liveStatus = 1` 行为。仅停止原生递减定时器，不修改网站接口或全局计时器。`visibilitychange`（变为可见）、`focus`、`pageshow` 和 `resume` 直接校准，无等待期。不刷新、不新建标签页、不进入直播、不自动播放，也不额外轮询网络。

禁用网站、路由离开、组件卸载时清理定时器和监听器；可见组件仍在倒计时则把准确剩余时间交回原生 watcher。主入口沿用现有站点启停机制，没有新增权限。

## 直播间普通／暖场组件（1.25.1）

2026-11-07 核实：直播间使用另一套组件，之前仅针对详情页的修复没有覆盖它。原生 `countDwon`（网站命名如此）与 `countDownForWarmUpVedio` 的 mounted 回调将 `enter_time` 存入闭包，每秒只 `+= 1`，所以黑屏、后台降频或休眠会使显示落后。原生 `timeConvert` 只负责将秒数写入 `time` 对象。

直播间适配器校验原生组件名称、`.count-down`／`.count-down-for-warm-up-vedio`、当前直播 ID 和格式化方法。读取原始 `pushzb_start_at`，按网站明确采用的中国标准时间（UTC+08:00）解析，不解析翻译后的显示文案，不使用可能不同于预定时间的 `zb_start_at`。初次接管以页面原有 `xe.alive.page.get/1.0.0` 响应的墙上时间与服务器 `enter_time` 配对，校准本机与服务器的偏移；响应记录不可用时使用绝对开播日期，而不是把已过时的进入时间重新锚到现在。新的 `enter_time` props 到达时以当前交付时间重新配对；开播日期单独变化时保留已校准偏移。

适配只包裹 `timeConvert` 的输入：无论网站原定时器何时执行，都按 `max(0, deadline - Date.now())` 显示；唤醒事件与每秒兜底校准也调用同一个原生格式化方法。保留原生 mounted、订阅检查、原始定时器和 `countDownDone` 事件，不重启组件、不调用自动订阅、不更改 `alive_state` 或播放器状态。到点只显示零，真实开播状态仍由网站原有直播流程决定。

恢复事件立即校准；组件状态已切换为直播中时不再写倒计时。停用或离开时恢复原始 `timeConvert`，清理插件监听和定时器，原生定时器不被插件重建。当前真实直播间检查时已进入直播中、倒计时组件被网站卸载，因此没有为测试修改真实开播时间或重新挂载真实组件。
