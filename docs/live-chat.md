# 直播消息即时反馈

## 适用范围与核实

适配已授权网站 `/p/t_pc/live_pc/pc/l_…` 的 `Inputer` Vue 文字消息组件，核对组件名、当前直播 ID、输入框、发送方法及消息列表。支持直播及直播结束后的回放讨论；图片、语音、回复消息和不支持的布局保留原行为。原生 `isOnReplay` 实际表示回复消息，不是视频回放；回放显示使用 `alive_state=3` 且 `is_lookback=1`。

2026-11-01 对真实直播页只读排查：当前 1.83.171 的 `Inputer.send` 先调用内容检查，之后 `sendMsg` 通过原生事件总线保存消息，再交给 IM；成功回调才清空输入框。一次用户自行发送的实测为 573ms 内容检查、386ms 保存、其后 463ms 通信确认／更新，共约 1.42s。实现和回归期间没有代替用户向真实直播间发送消息。

2026-11-06 对真实回放页只读核实：用户已发的消息能从 `xe.alive.get.history.msg/1.0.0` 读到完全匹配的消息 ID、本人与直播标识，但没有 `msg_tag`。原生保存成功响应 `is_limit_im` 为真时，会跳过 IM，插入无 `msg_tag` 的本地消息并执行完成回调；保存失败也会走类似本地兜底，因此仅凭本地气泡或完成回调无法判断是否已保存。本次没有重发真实消息，也没有取得用户当次发送的原始响应，不能据此断定当次具体命中了哪个 IM 分支。

## 实现约束

- 在 native `input_state` 开始发送时立即加一个只在本页显示的暗色消息提示，不向原生 `msgArr` 注入伪消息。
- 原始文字继续留在原生 Vue 状态供异步审核和发送使用；临时草稿框沿用原生 textarea 的样式属性，让用户看到空输入区并继续输入下一条。旧回调结束后才将这份草稿交回原生状态，避免被旧回调清空。等待期间不排队、不连发；Enter 提醒保留草稿，Ctrl+Enter 仍可换行。
- 仅为尚无 `comment_id` 的本次普通文字 payload 填入随机 32 位十六进制 ID，使用网站 `getSendMsgObj` 明确支持的客户端 ID 字段。已有 ID 保持不变；所有其余参数、审核、保存、IM、限流和提问元数据沿用原逻辑。
- 实时确认匹配本人的 `comment_id` 与非空 `msg_tag`。原生完成但没有实时回执时，先显示“正在核对是否已保存”，使用原生客户端仅请求固定的只读历史接口，读取当前房间最近 20 条讨论。每条消息最多查询三次，未命中时分别等待 1 秒和 2 秒；单次 8 秒超时，不后台无限轮询。
- 服务器响应成功，且消息 ID、本人账号、当前直播 ID 和文字消息类型完全匹配，才确认已保存；无 `msg_tag` 不再被当成失败。已有原生消息时撤掉本地状态并恢复原生气泡；只有服务器记录而列表尚未显示时保留“已保存到回放讨论／消息记录”的本地状态，不声称实时广播成功或老师已读。原生消息后续出现时自动合并。
- 网站本地兜底气泡在核实前临时隐藏，不删除或改写网站数据。审核拒绝显示“未发送”；历史查询异常、记录未找到、账号／直播／消息 ID 不匹配等都不能确认保存，有限查询结束后显示“未确认是否保存，请先检查消息记录，勿重复发送”。恢复编辑只在未确认状态下由用户主动操作，已有草稿不覆盖；“移除提示”只移除本地 UI，不撤回网站消息。
- 状态既有文字又有符号，不只靠颜色区分；使用 `role=status` 和温和播报，不将完整聊天内容反复播报。
- 禁用或离开页面后恢复原始方法、按钮、输入框和本地提示。若禁用时原生异步发送尚未结束，仅保留一次性原生编辑器保护监听，防止迟到的旧回调抹掉新草稿；完成或组件销毁后清理。切换到另一个直播上下文时不把旧草稿写入新上下文。

新增的请求仅限缺少实时回执后的有限只读历史核实，不改变网站发送请求或自动重发；查询不刷新原生消息列表或改变分页、滚动位置。停用、移除提示或离开页面后取消待查询任务，忽略迟到结果。没有网络拦截器、新增扩展权限或聊天存储。文字和状态只在当前页面内存与 DOM 中，不传给扩展后台、同步服务或维护者。它改善发送反馈，不缩短服务器的审核、保存和真实送达耗时。

## 测试

- `node tests/live-chat-smoke.js`：站点授权、文档身份、路由、顶层限制、安全文本、固定只读端点、有限查询和实际回放状态，不持久化聊天。
- `output/playwright/verify-live-chat.js`：隔离 Chrome 加载真实 MV3、Vue 2.6.14，并直接提取网站固定版本的原始 `Inputer.send/sendMsg` 方法；验证即时状态、原始请求顺序、授权／禁言门槛、审核拒绝、保存失败的伪成功、IM 失败、唯一确认消息、草稿保护、恢复编辑、禁用中的迟到回调和 SPA 清理。
- 测试请求均由本地夹具拦截，不向真实直播间发送消息。视觉截图位于 `output/playwright/live-chat-pending.png` 和 `live-chat-unconfirmed.png`。
- 回放回归覆盖 `isOnReplay=false` 的真实状态组合、保存成功但限制 IM、恢复单个原生气泡、保存成功但 IM 失败、保存／查询失败、错账号／直播／消息、查询次数限制、迟到确认和停用中的查询清理。

1.25.0 的[回放聊天跟随](live-chat-replay.md)使用独立的原生消息显示实例。跟随视图打开时，本次发送的状态放在单独的留言区，不加入过去的时间线；服务器确认后显示“已保存到课后留言”，已在留言列表中出现则合并，否则短暂显示后收起。切回原始列表或停止回放增强时重新协调发送提示位置，发送流程不变。
