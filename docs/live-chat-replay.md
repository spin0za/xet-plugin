# 回放聊天跟随

适用于已授权的 `/p/t_pc/live_pc/pc/l_…` 直播回放，保留网站播放器、聊天页签、发送与审核流程。无新增权限，不刷新页面，不设置视频播放位置、倍速、播放或暂停状态。

## 时间轴依据

2026-11-07 在真实回放只读验证：当前媒体清单为带 `ENDLIST` 的 HLS VOD，每段含 `EXTINF` 时长与 `EXT-X-PROGRAM-DATE-TIME`（PDT）。清单时长与播放器 `duration` 一致；录像起点为 2026-10-03 14:01:23 +08:00，而网站预定开课时间为 14:00、`zb_start_at` 为 13:59，不能以这两个开课字段推算零点。聊天接口提供 `created_timestamp`，可与清单的原始录像时间对应。

解析清单生成媒体时间／录制时间分段表，用消息时间反查播放位置。PDT 重叠时选最早覆盖片段，同一消息只显示一次；显式断流或剪辑间隙必须有新的 PDT，不推算缺失的录像。播放进度使用视频 `currentTime`，不使用网页打开时间或后台计时器，因此暂停、倍速、后台恢复和前后拖动均按实际媒体进度定位。

只接受带可靠时区的媒体 VOD 清单；没有 PDT、未结束的直播清单、无法确定的断流区间、倒序时间、获取失败或时长不匹配时保留原始聊天列表，明确提示并提供重试，不使用预定开课时间猜测。此精度受网站源清单的时间戳精度约束，不宣称逐帧级同步。普通独立视频页尚未提供同样的直播聊天上下文，不强行适配。

## 界面与交互

- 默认“跟随回放”，只显示当前视频进度及之前的录像内消息，不提前透露后续聊天。
- “讲解”和“讨论”各自按原生分区获取，沿用原生消息渲染器、头像、昵称、气泡和已有可见范围。新建独立的显示实例，不替换网站 `msgArr`、分页状态、原生 DOM 或发送方法；原列表保持挂载，随时可切回。
- 手动滚轮、触摸、点击聊天区域或键盘翻页后暂停跟随，不在播放时抢回位置；“返回当前进度”重新跟随。向上翻到已显示窗口顶部时扩展已缓存的历史显示，保留视口位置。
- “课后留言”只显示录像结束后发送的记录，注明这些留言不对应视频进度。录像前或录像未覆盖区间的消息仍可从“原始列表”查看，不错误归入课后留言。
- 显示视图覆盖原生列表时，发送状态使用独立的本次留言区；新留言不插入过去的聊天时间线。消息已保存不等于老师已读。

## 查询、缓存和退出

只读请求 `/_alive/api/alive/xe.alive.get.history.msg/1.0.0`：首次 `loadOrder=0`、空消息游标获取最早一页，之后 `loadOrder=1` 使用上一页末条消息 ID。请求每页 50 条（已验证服务器会限制单页数量），只读到当前进度附近；课后留言需要继续读到末页。检查直播来源和游标是否推进，失败后提供显式重试，不在每次播放事件上自动重试错误。

消息与索引只存在当前页面内存。已读过的时间段直接复用缓存；后台标签不依赖 `requestAnimationFrame` 才能继续完成查询。不把聊天内容返回扩展后台，不写入扩展存储、Chrome 同步或维护者服务器。独立渲染器覆盖原生“保存阅读位置”方法为空操作，避免自动跟随改写网站的阅读位置缓存。

切换原始列表、停用、页面或账号上下文变化后停止不再需要的跟随任务；停用时清理显示实例、事件、定时器、进行中的请求和本地状态，恢复原生列表，不操作视频。画质／线路切换导致媒体清单改变时，先停止使用旧时间表，重新验证新清单。

- 原直播发送反馈回归仍由 `output/playwright/verify-live-chat.js` 验证。
